## 왜 알아야 하나

코드를 받아 에디터에 옮기고 실행해 보고 다시 돌아와 수정을 요청하는 흐름은 왕복이 많습니다. 그 사이에 맥락도 끊깁니다.

Artifacts는 결과물을 별도 패널에 띄워 **그 자리에서 실행하고 고치게** 합니다. 결과를 보면서 "배경색 바꿔줘" 같은 수정을 이어가면 실시간으로 반영됩니다.

## 개념 잡기

다루는 유형은 대체로 이렇습니다.

| 유형 | 패널에서 되는 것 |
|---|---|
| 코드 | 문법 강조, 복사 |
| HTML | 브라우저 렌더링 확인 |
| React | 실제 클릭·입력 테스트 |
| SVG · 다이어그램 | 벡터 렌더링 |
| 마크다운 문서 | 서식 적용된 형태로 확인 |

핵심은 **반복 수정**입니다. 한 번에 완성하려 하지 말고, 띄워두고 조금씩 고치는 방식이 훨씬 빠릅니다.

## 바로 해보기

1. 간단한 HTML 대시보드를 요청해 패널에 띄웁니다.
2. 결과를 보면서 "색을 어둡게", "글자 키워줘" 같은 수정을 자연어로 이어갑니다.
3. 몇 번 반복한 뒤, 처음부터 완벽하게 요청했을 때와 걸린 시간을 비교합니다.

## 흔한 실수

- **❌ 한 번의 프롬프트로 완성본을 받으려 한다** — Artifacts의 강점은 반복 수정입니다. 대충 띄우고 고쳐 나가는 편이 빠릅니다.
- **❌ 결과만 보고 코드를 확인하지 않는다** — 렌더링이 멀쩡해도 코드가 엉성할 수 있습니다. 실제로 쓸 것이라면 읽어보세요.
