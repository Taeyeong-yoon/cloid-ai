**텍스트로 옮겨 적는 전처리 단계가 대부분 필요 없습니다.**

## 왜 알아야 하나

보고서 PDF, 에러 화면 캡처, 스캔한 서류를 다룰 때 예전에는 텍스트로 옮기는 작업이 먼저였습니다. 지금은 그대로 넣으면 됩니다.

같은 파일을 여러 번 쓸 거라면 매번 올리는 대신 **한 번 업로드하고 ID로 참조**하는 방식이 낫습니다.

## 개념 잡기

**직접 첨부** — 한 번 쓰고 말 파일. 문서 블록은 텍스트 블록보다 **앞에** 놓는 것이 권장됩니다.

**Files API 업로드** — 여러 요청에서 재사용할 파일. 업로드 후 받은 ID를 참조합니다.

인용(citations)을 켜면 답변의 어느 부분이 문서 어디에서 왔는지 표시됩니다. 근거 확인이 필요한 업무에서 특히 유용합니다.

이미지는 해상도가 높을수록 토큰을 더 씁니다. 세밀한 판독이 필요 없다면 미리 줄여서 넣는 편이 비용에 유리합니다.

## 바로 해보기

1. PDF 하나를 넣고 특정 조항이나 수치를 찾아달라고 요청합니다.
2. 인용을 켜서 답변의 근거 위치가 표시되는지 확인합니다.
3. 같은 파일로 질문을 여러 번 할 계획이라면 업로드 후 ID 참조 방식으로 바꿔 봅니다.

## 흔한 실수

- **❌ 같은 파일을 매 요청마다 다시 첨부한다** — 반복 사용할 파일은 업로드해두고 ID로 참조하세요.
- **❌ 고해상도 이미지를 그대로 넣는다** — 세밀한 판독이 필요 없다면 줄여서 넣으세요. 해상도가 곧 토큰입니다.
- **❌ 개인정보가 담긴 원본을 그대로 올린다** — 업로드 전에 가리거나 익명화하세요.

## 스스로 점검하기

**Q1. 인용(citations)을 켜면 무엇이 달라지나요?**

정답: 답변의 각 부분이 문서 어느 위치에서 나왔는지 표시되어 근거 확인이 쉬워집니다.
