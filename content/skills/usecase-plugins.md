**같은 저장소인데 개발 환경이 사람마다 다르면, 버그 재현부터 안 됩니다.**

## 왜 알아야 하나

팀원마다 스킬을 따로 만들고, 훅을 각자 설정하고, MCP 서버를 개별로 붙이면 환경이 전부 달라집니다. "제 환경에서는 되는데요"가 반복되고, 문제 재현조차 어려워집니다.

플러그인은 그 묶음을 하나로 만들어 배포합니다.

## 개념 잡기

**담을 수 있는 것**
- 스킬 (`SKILL.md` 묶음)
- 슬래시 명령
- 훅 설정
- MCP 서버 연결 정보
- 서브에이전트 정의

**도입 순서**
1. 한 사람이 쓰던 설정을 정리 — 실제로 쓰이는 것만 남깁니다
2. 팀 저장소에 플러그인으로 묶기
3. 새로 합류한 사람이 **설치만으로** 같은 환경이 되는지 확인

3번이 검증 기준입니다. 추가 설명이 필요하다면 아직 덜 묶인 것입니다.

## 바로 해보기

1. 지금 내 설정에서 팀원 두 명 이상이 쓸 만한 것만 골라냅니다.
2. 그것들을 플러그인으로 묶어 저장소에 올립니다.
3. 팀원 한 명에게 설치만 시키고, 추가 설명 없이 같은 결과가 나오는지 확인합니다.
4. 차이가 나는 부분을 찾아 플러그인에 마저 넣습니다.

## 흔한 실수

- **❌ 처음부터 모든 설정을 다 넣는다** — 실제로 두 명 이상이 쓰는 것부터 넣으세요. 안 쓰는 설정은 유지보수 부담만 됩니다.
- **❌ 자주 바뀔 설정을 팀 표준에 넣는다** — 팀 표준이 되는 순간 바꾸기 어려워집니다. 변동이 잦은 건 개인 영역에 두세요.

## 스스로 점검하기

**Q1. 플러그인이 잘 만들어졌는지 판단하는 기준은?**

정답: 새로 합류한 사람이 설치만으로 같은 환경이 되는가입니다.

**Q2. 무엇부터 넣어야 하나요?**

정답: 실제로 두 명 이상이 쓰고 있는 설정부터입니다.
