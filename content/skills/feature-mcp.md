**모델이 모르는 것은 우리 회사 데이터입니다. MCP는 그걸 연결하는 통로입니다.**

## 왜 알아야 하나

모델은 일반 지식은 알아도 **우리 데이터**는 모릅니다. 사내 위키, 이슈 트래커, 데이터베이스, 로컬 파일 같은 것들이죠.

예전에는 도구마다 연동 방식을 따로 만들어야 했습니다. MCP는 그걸 표준화해서, 한 번 만든 서버를 Claude Code·데스크톱·API에서 같은 방식으로 쓰게 합니다.

## 개념 잡기

**Claude Code에서는** 설정에 서버를 등록하면 세션에서 바로 도구로 노출됩니다.

**API에서는** 서버 정의와 툴셋을 **함께** 넘겨야 합니다. 하나만 있으면 요청이 거부됩니다.

```js
mcp_servers: [{ type: "url", name: "linear", url: "..." }]
tools:       [{ type: "mcp_toolset", mcp_server_name: "linear" }]
```

인증은 분리해 관리하는 것이 권장됩니다. 에이전트 정의에는 **주소만** 두고 토큰은 별도 보관소에 넣습니다. 재사용 가능한 설정에 비밀이 섞이지 않게 하려는 설계입니다.

## 바로 해보기

1. 파일시스템 MCP 서버를 하나 연결합니다.
2. 접근 가능한 경로를 **필요한 폴더 하나로만** 제한합니다.
3. 간단한 작업을 시켜 도구가 실제로 호출되는지 확인합니다.
4. 권한을 넓혔을 때와 좁혔을 때 각각 무엇이 가능한지 비교해 봅니다.

## 흔한 실수

- **❌ 편의를 위해 넓은 권한을 준다** — 연결한 도구가 할 수 있는 일이 곧 AI가 할 수 있는 일입니다. 최소 권한이 원칙입니다.
- **❌ 서비스의 일반 API 키를 MCP 인증에 그대로 쓴다** — 호스팅형 MCP 서버는 대개 OAuth 토큰을 요구합니다. 서비스 API 키와 다른 체계인 경우가 많습니다.
- **❌ API에서 서버만 등록하고 툴셋을 빠뜨린다** — 둘 다 있어야 합니다. 하나만 넘기면 요청이 거부됩니다.

## 스스로 점검하기

**Q1. MCP가 필요 없는 경우는?**

정답: 일반 상식 질문처럼 모델이 이미 아는 내용을 다룰 때입니다.

**Q2. MCP 연결에서 가장 중요한 보안 원칙은?**

정답: 최소 권한입니다. 도구의 접근 범위가 곧 AI의 행동 범위입니다.
