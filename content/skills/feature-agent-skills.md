**프롬프트는 그 대화에서 끝나고, Skill은 남습니다.**

## 왜 알아야 하나

업무에는 형식이 반복되는 일이 많습니다. 주간 보고 정리, 릴리스 노트 작성, 데이터 점검 같은 것들이죠. 매번 같은 설명을 다시 하는 건 시간 낭비이고, 설명이 조금씩 달라지면 결과도 흔들립니다.

Skill은 그 방법을 **파일로 고정**합니다. 등록해두면 관련된 요청이 왔을 때 Claude가 알아서 꺼내 씁니다.

## 개념 잡기

```
my-skill/
  SKILL.md        # 언제 쓰는지 + 어떻게 하는지
  reference.md    # 필요할 때만 읽는 상세 자료
  script.py       # 함께 쓰는 도구 (선택)
```

가장 중요한 건 `SKILL.md` 앞부분의 **설명(description)** 입니다. 이게 호출 트리거이기 때문입니다.

- ❌ "보고서를 작성하는 스킬입니다" → 무엇을 하는지만 있음
- ✅ "주간 실적 보고서를 만들 때 사용. 매출·이슈·다음 주 계획 세 섹션으로 구성" → **언제** 쓰는지가 있음

쓸 수 있는 곳은 세 군데입니다. **Claude Code**(프로젝트·개인 설정), **API**(컨테이너에 연결, `pptx`·`xlsx`·`docx`·`pdf` 기본 제공), **Managed Agents**(에이전트당 최대 20개).

## 바로 해보기

1. 이번 주에 두 번 이상 반복한 작업을 하나 고릅니다.
2. `SKILL.md`를 만들고 첫 줄에 **언제 쓰는지**를 씁니다. 기능 설명이 아니라 호출 조건입니다.
3. 그 아래에 단계와 판단 기준을 적습니다. 세부 자료는 별도 파일로 빼세요.
4. 실제로 호출해 보고, 안 불려 나오면 설명(description)의 트리거 조건을 손봅니다.

## 흔한 실수

- **❌ 기능 설명만 쓰고 호출 조건을 빼먹는다** — Skill이 안 불려 나오는 원인 대부분이 여기입니다. "언제 쓰는가"를 먼저 쓰세요.
- **❌ 모든 세부 절차를 SKILL.md에 몰아 넣는다** — 설명은 매 요청마다 컨텍스트에 실립니다. 분량이 곧 비용이니 상세 자료는 참고 파일로 분리하세요.
- **❌ 매번 결과가 달라야 하는 창의적 작업을 Skill로 만든다** — Skill의 가치는 반복과 일관성에서 나옵니다. 형식이 고정된 일에 쓰세요.

## 스스로 점검하기

**Q1. Skill이 필요한 순간에 호출되지 않는다면 어디를 먼저 봐야 하나요?**

정답: `SKILL.md`의 description입니다. "언제 쓰는지"가 없으면 트리거되지 않습니다.

**Q2. SKILL.md를 짧게 유지해야 하는 이유는?**

정답: 설명이 매 요청 컨텍스트에 실려 토큰 비용이 되기 때문입니다. 상세 내용은 참고 파일로 뺍니다.
