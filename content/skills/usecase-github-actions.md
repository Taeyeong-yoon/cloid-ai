**"중요한 것만 알려줘"라고 요청하는 순간, 진짜 버그가 걸러집니다.**

## 왜 알아야 하나

AI 리뷰를 붙였는데 기대만큼 못 잡는다는 이야기가 많습니다. 원인은 대개 모델이 아니라 **요청 방식**입니다.

"중요한 것만", "보수적으로", "사소한 건 빼고" 같은 지시를 넣으면 모델이 그걸 충실히 따릅니다. 조사는 똑같이 하고, 확신이 낮은 항목을 스스로 걸러냅니다. 정밀도는 올라가지만 **놓치는 버그가 늘어납니다.**

## 개념 잡기

역할을 나누는 것이 핵심입니다.

**AI가 잘하는 것**
- 놓치기 쉬운 경계 조건·예외 처리 누락
- 변경과 무관하게 깨질 수 있는 지점
- 반복되는 실수 패턴

**사람이 해야 하는 것**
- 이 변경이 제품 방향에 맞는지
- 설계 선택이 타당한지
- 우선순위와 범위 판단

리뷰 요청은 이렇게 씁니다.

**발견한 문제를 확신이 낮은 것까지 전부 보고하고, 각 항목에 심각도와 확신도를 표시해줘. 걸러내는 건 다음 단계에서 한다.**

넓게 받고 사람이 거르는 편이, 좁게 받고 놓치는 것보다 낫습니다.

## 바로 해보기

1. 최근 PR 하나를 골라 "중요한 것만" 요청으로 리뷰를 받아 봅니다.
2. 같은 PR을 "전부 보고 + 심각도·확신도 표시" 요청으로 다시 받습니다.
3. 두 결과의 항목 수와, 실제 버그가 몇 개씩 잡혔는지 비교합니다.
4. 쓸 만한 쪽을 CI에 붙이되, 코멘트는 상위 심각도만 남기도록 필터를 겁니다.

## 흔한 실수

- **❌ 리뷰 요청에 "보수적으로", "사소한 건 빼고"를 넣는다** — 모델이 그대로 따르면서 진짜 버그까지 걸러냅니다. 필터링은 받은 뒤에 하세요.
- **❌ PR 본문을 비워두고 코드만 넘긴다** — 무엇을 왜 바꿨는지 알아야 "의도와 다른 동작"을 잡습니다. 코드만 주면 표면적 지적에 그칩니다.
- **❌ 모든 지적을 자동 코멘트로 남긴다** — 코멘트가 많으면 아무도 안 읽습니다. 상위만 노출하고 나머지는 접어두세요.

## 스스로 점검하기

**Q1. AI 리뷰의 recall이 낮아 보일 때 가장 먼저 볼 곳은?**

정답: 리뷰 요청 문구입니다. 심각도 필터를 걸어두면 모델이 스스로 걸러냅니다.

**Q2. 리뷰 품질을 높이는 입력은?**

정답: 변경 의도와 맥락입니다. PR 본문이 비어 있으면 표면적 지적만 나옵니다.
