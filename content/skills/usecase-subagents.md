> 서브에이전트는 공짜가 아닙니다. 맥락을 새로 세팅하는 값을 매번 냅니다.

## 왜 알아야 하나

서브에이전트는 각자 맥락을 세팅하고, 조사하고, 보고합니다. 그다음 본 흐름이 그 보고를 읽습니다. 이 왕복이 비용입니다.

일이 그 비용을 넘어설 만큼 커야 이득이 납니다. 작은 일에 쓰면 직접 하는 것보다 느리고 비쌉니다.

## 개념 잡기

**쓸 만한 경우**
- 여러 모듈을 동시에 조사해야 할 때
- 서로 독립적인 작업을 병렬로 돌릴 때
- 넓은 코드베이스에서 후보를 찾아야 할 때

**직접 하는 게 나은 경우**
- 파일 몇 개 읽고 끝나는 일
- 간단한 검색
- 결과 검증 (본 흐름에서 하는 편이 정확)

판단이 애매하면 이렇게 물어보세요. **"내가 직접 하면 도구 호출 몇 번인가?"** 한 자릿수라면 직접 하는 게 낫습니다.

## 바로 해보기

1. 여러 파일을 훑어야 하는 작업을 하나 골라 서브에이전트에게 위임합니다.
2. 같은 작업을 직접 처리해 보고 **소요 시간과 토큰**을 비교합니다.
3. 독립적인 작업 여러 개를 한 번에 띄워 병렬 효과를 확인합니다.
4. 결과를 받은 뒤 다시 직접 확인하고 싶어지는지 관찰합니다 — 그렇다면 위임 지시가 부실했던 것입니다.

## 흔한 실수

**❌ 띄워놓고 나중에 다시 설명한다**

→ 처음 지시를 정확히 주세요. 재브리핑은 왕복 비용을 두 배로 만듭니다.

**❌ 받은 결과를 본 흐름에서 다시 검증한다**

→ 위임했으면 신뢰하세요. 다시 확인할 거면 처음부터 직접 하는 게 빠릅니다.

**❌ 작은 작업을 여러 조각으로 쪼개 병렬로 돌린다**

→ 병렬은 독립적이고 규모 있는 작업에서만 이득입니다. 개수를 낮게 유지하세요.

</details>
