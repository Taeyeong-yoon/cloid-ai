**도구 설명은 사람이 읽는 문서가 아니라, 모델이 읽고 판단하는 근거입니다.**

## 왜 알아야 하나

모델이 계산하고 검색하고 저장하려면 외부 기능이 필요합니다. 도구 사용은 그 연결 규격입니다.

가장 흔한 실패는 도구가 있는데도 **불려 나오지 않는 것**입니다. 원인은 대개 설명이 부실해서입니다.

## 개념 잡기

도구 정의는 셋으로 이뤄집니다. 이름, 설명, 입력 스키마.

이 중 **설명이 가장 중요합니다.** 무엇을 하는지만 쓰지 말고 **언제 부르는지**를 쓰세요.

- ❌ "날씨 정보를 반환합니다"
- ✅ "사용자가 특정 지역의 현재 날씨나 예보를 물을 때 호출합니다"

**병렬 호출**은 기본으로 켜져 있습니다. 한 응답에 여러 도구 호출이 들어올 수 있고, 결과는 **하나의 메시지에 모아서** 돌려줘야 합니다. 나눠 보내면 모델이 병렬 호출을 점점 안 하게 됩니다.

실패한 도구도 결과를 돌려주세요. 오류 표시와 함께 보내면 모델이 다른 방법을 시도합니다. 그냥 빼먹으면 흐름이 깨집니다.

## 바로 해보기

1. 도구를 하나 정의하되 설명에 **호출 조건**을 명시합니다.
2. 일부러 애매한 질문을 던져 도구가 불려 나오는지 확인합니다.
3. 불려 나오지 않으면 설명을 고칩니다. 프롬프트를 강화하기 전에 설명부터 보세요.
4. 도구를 일부러 실패시키고, 오류 결과를 돌려줬을 때 모델이 어떻게 대응하는지 관찰합니다.

## 흔한 실수

- **❌ 도구 설명에 기능만 적는다** — 호출 조건이 없으면 필요한 순간에 불려 나오지 않습니다.
- **❌ 병렬 호출 결과를 여러 메시지에 나눠 보낸다** — 한 메시지에 모아 보내세요. 나누면 모델이 병렬 호출을 줄입니다.
- **❌ 실패한 도구 호출을 결과 없이 넘긴다** — 오류 표시와 함께 결과를 돌려줘야 모델이 복구를 시도합니다.

## 스스로 점검하기

**Q1. 도구가 호출되지 않을 때 가장 먼저 볼 곳은?**

정답: 도구 설명입니다. 언제 호출하는지가 적혀 있어야 합니다.

**Q2. 여러 도구가 동시에 호출됐을 때 결과는 어떻게 보내나요?**

정답: 하나의 메시지에 모두 담아 보냅니다.
